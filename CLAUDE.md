# Working on this repository

AI-native platform for Belgian real estate agencies. Read README.md for the architecture.

## Rules

- **New behaviour goes in a tool** in `packages/core/src/tools`, registered in `packages/core/src/index.ts`. Pages and server actions call `runTool(tools.x, ctx, input)`; never query the database for domain data directly from `apps/web` (Better Auth session lookups and settings reads in `lib/context.ts` are the exception).
- **Every tool scopes by `ctx.agencyId`.** No exceptions; this is the tenant boundary.
- **Mutating tools call `recordEvent`** with a dotted type such as `appointment.booked`.
- **AI actions that need approval** create a row in `proposals` instead of acting.
- **Times**: store UTC (`timestamptz`); display and compute day boundaries in Europe/Brussels with `@viewing/core/time`.
- **Client components** must not import `@viewing/core` (it pulls in the database). Use `@viewing/core/time` or pass data as props.
- **Schema changes**: edit `packages/db/src/schema`, run `pnpm db:generate --name <change>`, commit the SQL. Auth tables are generated by `npx auth@<better-auth version> generate`.
- **Design**: tokens in `apps/web/app/globals.css`. Near-monochrome, thin borders, status as small coloured dots. Violet (`ai` colour) only for things an AI agent did or proposes. Check light, dark and phone width (390px). On phones: bottom tab bar (`components/mobile-nav.tsx`), card lists instead of tables (`md:hidden` list + `hidden md:table`), no hover-only or drag-only actions.
- **Data residency**: everything in the EU (Vercel `fra1`, Neon `eu-central-1`). New services must offer EU hosting.

## Checks before pushing

`pnpm typecheck`, `DATABASE_URL=… pnpm test` (database tests are skipped without it) and `pnpm --filter @viewing/web build`.

## Booking

- Slots come from `computeSlots` (`packages/core/src/planner/availability.ts`), a pure function with unit tests. Keep it pure.
- Booking and rescheduling take a per-agent advisory lock inside a transaction and re-check the slot; never insert appointments any other way.
- Pages without login (`app/(public)`) resolve the agency through `@viewing/core/public` and then call tools with `publicContext(agencyId)`.

## Planner agent and inbox

- The planner lives in `packages/core/src/planner/agent.ts`: triage (category, priority, language, summary), then a draft reply saved as a `proposals` row with `toolName: "conversations_reply"`. Approving runs that tool, optionally with the human's edits.
- Claude is called only through `packages/core/src/ai/client.ts` (`generateStructured`, model `claude-opus-5-5`, server-side refusal fallback). Every AI path has a template or rules fallback, so the product works without `ANTHROPIC_API_KEY`; the UI must say which one produced a draft.
- Offered times always come from the booking engine and are appended by `composeMessage`; the AI never writes times or links itself.
- Outbound messages are stored with `delivery: "simulated"` until Outlook/Gmail/WhatsApp are connected. Never present them as sent.
- Client-facing text exists in NL, FR and EN (`planner/language.ts`, `apps/web/lib/widget-i18n.ts`).
- Client actions without a message (booking in the widget, moving or cancelling through the link) go through `noteClientAction`: a system note in the client's preferred channel (WhatsApp if opted in, else email) plus a draft for approval. Nothing is sent to a client without a human approving it.

## Website widget

- `apps/web/app/widget.js/route.ts` is the embed script agencies put on their site. It resolves the listing by reference (`/api/widget/resolve`) and picks the agent whose name appears first on the page; the booking goes to that agent, else to the listing's responsible agent.
- The same script shows a floating valuation button (bottom right, agency colour, full screen on phones) on every page without a `data-viewing-valuation` placeholder. Agencies switch it in the back office (`settings_update_widget`); `data-launcher="off"` on the script turns it off per page. The script must stay plain ES5 in a shadow root, so agency CSS can't break it.

## Valuations and recommendations

- The estimate is computed by `packages/core/src/valuation/model.ts` (pure, tested): Statbel municipality median × adjustments, blended with the agency's own sales nearby. AI never produces the amounts.
- Reference data (`market_prices`, `postcodes`) is shared by all agencies and filled by `packages/db/src/import`; see docs/data-import.md.
- The phone must be verified before an estimate is shown. With `WHATSAPP_VERIFY_NUMBER` set, owners send a prefilled code from WhatsApp; without it the code is shown on screen as a demo.
- Comparables are shown by street only, never with house number.
- Recommendations use plain scoring (`planner/similarity.ts`); suggestions to clients are drafts in the inbox like everything else.
